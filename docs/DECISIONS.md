- 2026-10-22 — Joint conventions, from A's (Vedant's) written answers to B's questions; recorded by B, confirmed by A's merge of this entry.
  - **Backend:** HQQ is primary for the next development experiment. It ran INT4 and INT2 caches on the T4; the attempted Quanto build failed there, which does not establish that every Quanto configuration is incompatible with a T4.
  - **Validation dtype:** FP32. The tolerance is not relaxed to about 0.016 to make FP16 pass. FP16 may later be a separate deployment condition, only after its ordinary/identity discrepancies are characterized and its tolerance is justified before any quantization effect is interpreted.
  - **Environment:** torch 2.9.1+cu128, transformers 5.5.4, HQQ 0.2.8.post1. One shared, reproducible installation specification is to be derived from the successful day-six/day-seven environment; `requirements-week1.txt` is a candidate file, not that lock. Every run keeps its complete environment freeze, and ordinary/identity checks are rerun in the shared environment.
  - **Model precision:** FP32 weights for the next paired experiment, with ordinary and quantized-cache conditions using the same loaded checkpoint. The final paper's deployment scope remains a joint decision.
  - **Masks:** explicit valid-token masks; all ones for current unpadded, batch-size-one inputs; for padded batches, masks come from sequence lengths or tokenizer padding metadata, never from token identity (the pad ID equals a genuine end-of-turn token). Batched operation needs its own validation before use.
  - **Reference scoring:** include the final end-of-turn token; save exact reference token IDs and counts; same convention for parallel and sequential scoring. This is a scoring convention, not an annotation label. Earlier diagnostics that excluded it stay separately identified.
  - **Prompts:** frozen full-model tokenizer and chat template, date 10 Apr 2025, system message "You are a helpful assistant."; reuse the exact rendered prompts and token IDs; record tokenizer revision and template hash.
  - **Generation:** greedy, one beam, at most 64 new tokens for benchmark questions, identical stopping settings across models and cache conditions; truncated outputs are preserved and flagged.
  - **Primary measurement:** generation-based factual disclosure; reference log-probabilities and ROUGE are secondary. Correctness stays separate from refusal behavior (a refusal revealing the requested fact still discloses it). Partial and ambiguous cases are reported explicitly with a fixed question population.
  - **Evaluator:** emits schema-v2 item records and manifests directly, with distinct model/condition identities, preserved errors and retries, factual labels left unscored until annotation, and log-probability sums with token counts. Shared, versioned loading/prompt/tokenization/scoring helpers are preferred over copied code, with parity first demonstrated on the frozen fixtures and an independent control kept.
  - **Process:** reciprocal review: each person reviews and merges the other's pull requests. The earlier direct-push exception remains a specific exception.
