The installed transformers 5.5.4 `QuantizedLayer.update` flushes only when `self.keys.dim() == 4 and self.keys.shape[-2] + 1 >= self.residual_length`. After a flush the buffer is reset to a 1-D empty tensor, so the next decoded token always goes into the full-precision buffer. Write counts predicted from this code (residual 0 or 1 -> 4, residual 4 -> 2, residual 128 -> 1) matched the observed counts. Implications (inference from the code, for the residual-policy decision): residual 0, 1 and 2 behave identically in this version, and every other decoded token stays in full precision for one step; prompt K/V is quantized after prefill regardless of residual; each flush re-quantizes the whole dequantized cache, unlike engines that quantize each token once on write. The equal max change at residual 4 and 128 suggests the largest change comes from reading the quantized prompt, before any flush. Single artificial fixture, one run per setting; no claim about forgetting or recovery. Still to run: long prompt, repeatability. Reports remain in the Colab session.
